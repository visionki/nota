# 后台任务与执行数据的边界

后台任务列表按用户交办组织，每个根任务包含查询和结果交付阶段。服务端保留各阶段的执行细节和回执。

| 界面     | 收录内容                                                       |
| -------- | -------------------------------------------------------------- |
| 对话     | 主 Agent 的问答、即时工具回执、澄清、对应过程和失败重试        |
| 语音便签 | 文件上传、转写、预处理、批次整理及业务回执                     |
| 后台任务 | 定时或外部触发的一次独立查询，从开始执行直到交付结果           |
| 通知     | 到时提醒、新结果与待处理事件，点击进入对应消息、便签或后台任务 |

普通问答与工具交办、主 Agent 的后台汇报、录音预处理和批次汇总均不单独进入后台任务列表。后端在 Worker 执行，并不自动使它成为用户眼中的后台任务。当前独立执行入口为 schedule / webhook；旧版由主 Agent 执行的定时/外部任务仍作为历史任务保留。

## 一次交办，一个列表项

`GET /api/background-tasks` 读取业务任务视图，避免使用聊天 bootstrap 的操作列表作为回退。后台根操作是稳定任务 ID；同一执行尝试的派生汇报与后续补答归并为“结果交付”阶段，不单独计数。原始 `/api/operations`、消息、工具回执和过程接口继续服务聊天、恢复和排查。

研究完成、汇报仍在排队或执行时，整体保持进行中；汇报等待补答时显示待确认；汇报失败时显示待处理，重试目标为已保存的汇报，不重跑查询或额外扣次。原始查询失败则重试原始查询。只选择与根操作当前尝试匹配的汇报，避免旧失败污染重试后“无变化”的新结果。

列表默认显示进行中与待处理；已完成和已取消进入历史，也可查看全部。无变化检查仍可查看历史结果，不创建通知或主 Agent 汇报。分页按稳定的创建时间与 UUID 游标读取，每页 25 条；计数覆盖当前账号的全部根任务，与聊天数量无关。同一事务创建的相同时间戳不会造成分页遗漏。

详情默认展示查询/交付阶段、阻塞原因及可用动作。已经回到对话的结果通过按钮定位具体消息；不在详情重复整段主 Agent 回复。没有聊天交付的无变化结果在任务中保留。原始交办内容和查询过程按需展开，不把 token、上下文压缩或内部调度指令作为管理首页内容。

## 失败、旧链接与录音

`/api/operations/:id/destination` 按所属业务定位：普通交办定位聊天最新答复，后台查询及汇报定位根任务，文件及录音批次定位便签；需要补答的交付仍定位对话并携带补答目标。`/api/operations/:id/state` 为旧失败消息提供轻量状态，只允许当前最新失败答复显示重试入口。

新版入口为 `#tasks`；`#activity` 兼容跳转。旧链接中的内部汇报定位其根任务；普通聊天操作定位对话，录音操作定位便签。所有解析、详情和游标都校验账号归属。

录音详情的“查看工具回执”进入当前便签的版本与来源，使用该录音批次的实际 Agent 操作读取行动过程。失败通知优先定位对应失败文件；录音阶段不会显示为独立后台任务或提前宣称整体完成。

## 验证

`pnpm test:tasks` 使用隔离 PostgreSQL 和受控模型验证收录范围、阶段归并、交付重试、补答继续、无变化历史、尝试隔离、取消、聊天/便签跳转、稳定分页与账号隔离。`tests/browser/tasks.spec.ts` 与通知浏览器测试覆盖 PC/H5 的完整入口、历史消息重试、结果交付、旧链接和分页，不调用付费模型。
