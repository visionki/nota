# 运行中引导与连续更正

用户在前台交办运行或等待补答时发来的新消息，通过 Pi SDK 原生引导继续处理同一交办。补充沿用会话、已有动作回执和额度预占。后台查询拥有独立会话，汇报期间发送的前台消息会形成新的交办。详见[后台任务](BACKGROUND_TASKS.md)。

## 执行规则

1. API 在用户锁及操作行锁内决定引导或新建。chat_inputs 持久保存请求 ID、正文、版本、目标交办和接入状态；同键重试不会重复插入或扣次。
2. Worker 将补充交给 Pi 原生引导队列。只有用户消息真正进入 SDK 历史后才标记“已接入”；重启会从数据库恢复当前目标、更正和实际回执。
3. 每次模型请求有输入版本。业务写入在同一事务检查版本：若新的更正已经到达，旧参数返回“已跳过”，不执行。已提交的结果作为事实保留，后续通过 update_reminder / update_event / update_todo 修改原对象。
4. 最终交付前锁定操作并检查版本。补充先到则继续同一交办；本轮已经封口时返回 turn_finished，前端使用同一请求 ID 转为后续新交办，不把消息丢在已结束的轮次。
5. 等待补答时的更正继续原任务；运行中的更正会清除已过时的等待问题。已经取消的目标或被较新交互取代的旧问题不会劫持默认输入。
6. 原始交办时间及已确定日期保留。“后天 3 点”改为“6 点”只更改小时，跨午夜、重试或压缩都不重新移动日期。已经投递的通知不能假装撤回。

## 验证

`pnpm test:steering` 使用 PostgreSQL、Pi SDK 和受控的流式模型接口，覆盖并发额度、重复提交、账号隔离、结束竞争和多次更正。`pnpm test:live` 可用真实 GMI 接口验证运行中更正。
