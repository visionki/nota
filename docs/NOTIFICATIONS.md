# 通知边界

通知集中显示到时提醒、后台任务的新结果和需要处理的事项。每条通知可回到对应对话、后台任务或语音便签。

| 事件                                                                 | 通知                                   |
| -------------------------------------------------------------------- | -------------------------------------- |
| 普通问答、当前对话追问、即时创建或修改日程/待办/提醒                 | 不创建；回执留在对话                   |
| 用户设置的提醒实际到时                                               | `reminder` / 到时提醒                  |
| 后台查询、外部触发或录音批次交付新结果                               | `task_result` / 任务结果，一次交付一条 |
| 异步任务缺少信息、录音批次存在失败项、最终执行失败或自动任务未能启动 | `attention` / 待你处理                 |
| 排队、执行步骤、文件预处理阶段、自动重试                             | 不创建；留在所属任务、对话或便签中     |

## 事件与阅读

通知关联 `message_id` 和明确的 `object_type/object_id`。提醒消息与通知在同一事务保存；后台仅在 Nota 交付结果时创建通知，研究过程与派生汇报不重复通知。按业务事件键去重，不依赖页面是否打开。标题描述具体事情，正文是纯文本短摘要，完整内容保留在对应消息及所属任务中。

对话真正推进阅读位置时，同一账号在该位置之前的关联通知同步已读。自动确认仅覆盖当前视口已显示的消息；打开页面、获取历史、SSE 到达、页面隐藏、弹窗遮挡或结果尚在定位时不触发阅读。主动“跳转到未读”“标为已读”仍确认本次已接收的最新消息；迟到的新消息不会被旧回执清除。

`read_at` 表示看过，`resolved_at` 表示这次阻塞已处理。全部已读只改变阅读状态。补答、重试或取消解除对应阻塞；录音批次的失败提示在该批失败项均已重试后解除。看过但尚未处理的通知仍显示“待处理”。暂停自动任务或下一次成功启动可解除该任务未执行的提示；同一任务连续启动失败只保留一个尚未解决的事件。

通知点击定位具体消息（包括已不在最新历史页的消息）、所属任务或对应自动任务。即时交办失败定位聊天中的错误和重试入口；后台查询或汇报失败定位同一根任务；录音处理失败定位语音便签。待补答的后台结果沿用同一次汇报操作继续处理，保留原始任务与用户补答，不重复预占处理额度。

## 自动任务的通知策略

新建和现有自动任务均可选择 `always`（每次交付）或 `on_change`（有新变化才通知），默认保持每次交付。Agent 的 `create_schedule` 也支持此字段；调度时固化到本次执行输入。

后台可读取该自动任务的上次成功结果，通过后台专用的 `report_task_outcome` 保存 `summary / has_update / needs_input`。明确无变化且不需用户补充的 `on_change` 成功结果只保留在后台任务历史，不创建主会话汇报和通知。首次发现、无法确认变化或模型没有返回结构化判断时保守交付；失败和需要补充不会被“无变化”策略吞掉。变化判断取决于任务提供的范围、证据与上次结果，不对自然语言正文做关键词猜测。

## 升级与验证

幂等 schema migration 3 增加事件关联、处理状态和自动任务策略；归档旧版普通聊天的完成/追问通知，不删除聊天或操作历史。有效提醒和后台结果保留并转换为三种新语义，能关联到消息的历史通知会按既有阅读位置同步已读。归档项不进入通知列表和未读计数。

`pnpm test:notifications` 在独立 PostgreSQL 和受控本机模型供应商下验证触发边界、去重、精确阅读、无变化抑制、补答继续、失败重试、账号隔离与升级幂等。`tests/browser/notifications.spec.ts` 在 PC/H5 验证分类、历史结果定位、待处理独立状态及失败任务入口；使用真实 HTTP、数据库与界面，不调用付费模型。
