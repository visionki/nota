# 对话界面与已读进度

录音预处理、Agent 对话和阅读状态分别管理。

## 页面状态

- 没有交互时显示居中的输入框、简短欢迎语和录音/安排/检索入口。
- 用户发送消息或主 Agent 被触发后，欢迎语、日期与建议入口收起，对话使用单列阅读布局。
- 文件上传、转写、分析、动态处理窗口均留在语音便签中，不给聊天插入进度消息，也不作为后台任务列表项。SSE 中的文件事件不能临时创建对话任务。
- 窗口就绪后仍按原有持久事件激活主 Agent，输入摘要、候选和来源索引；Agent 的实际文字、工具调用和最终答复保留。
- 工具出现前只显示流式文字及运行状态。实际调用工具后才有过程折叠器；结束时整体收起。已完成的普通答复无工具时不显示空折叠器。
- 普通答复、即时工具交办和澄清不进入后台任务列表。交办失败时，在对应消息下提供重试；只在该操作当前仍失败且该条消息是最新答复时显示。历史失败消息通过独立状态查询确认重试条件，不依赖最新 60 条操作。显式重试后回到最新对话以接收新结果；bootstrap 按最近更新时间返回操作，恢复旧交办时仍能显示实时进展。

## 一条账号阅读进度

`conversation_reads` 每个用户一行：`last_read_message_id` 定位消息，`last_read_seq` 为其稳定排序位置。消息 UUID 不直接比较大小；序号通过 bigint 比较，不给每条消息存已读标记。未读数量只计算该位置之后的 assistant 消息，涵盖正常答复、自动汇总和到点提醒。

接口只允许推进当前账号已有消息的位置。并发或迟到的较早回执不会回退进度；重复回执不生成重复状态事件。已读更新不调用模型、不进入主会话，也不使用 AI 额度，通过 `chat_read` SSE 同步其他页面。

打开页面、加载历史和接收 SSE 都不会直接标为已读。只有当前可见且有焦点的聊天页，最早未读消息实际进入消息视口并停留 650ms，才推进到当前视口实际显示的最后一条消息。页面隐藏、用户在其他功能页、未读还在屏幕外或尚未加载时不推进；弹窗覆盖及通知结果定位尚未完成时也不推进。关联到这些消息的通知同步已读，后面的结果通知保持未读；已读不解除任务的待处理状态。

顶部未读条提供“跳转到未读”和“标为已读”。主动跳转会加载该消息所在页、定位到未读起点，并确认这次已收到的消息；标记操作携带具体最新消息 ID，之后才到达的消息继续未读。分界线只标识重新打开对话时已经积累的未读边界；持续停留在聊天页时收到的新答复不插入分界线。对应消息确认已读后，分界线移除。

## 历史分页

Bootstrap 返回 `has_older_messages`。`GET /api/messages` 支持互斥的 `before`、`after` 或 `around`，按真实消息序号返回 `has_before` / `has_after`。到第一条后隐藏“查看更早的对话”，不依赖“恰好取到 50 条”猜测是否还有历史。

未读位置超出最新 100 条时，按 UUID 加载对应历史页及少量前文；此时使用连续的历史窗口，不把中间尚未读取的消息与最新页拼接。支持继续加载后续对话和回到最新。

历史仍通过“查看更早的对话”点击加载，每页 50 条。位置恢复记录当前可见消息 ID 及其相对视口的偏移；在响应返回时读取用户的实际位置，插入前文后在绘制前恢复。列表尾部新增内容不计入补偿，图片或其他内容延迟改变高度时按消息位置继续校正。用户主动滚动、跳转未读、回到最新和离开页面时尊重当前操作，失效的历史请求不能再写入新视图。

## 验证

`pnpm test:conversation` 覆盖分页边界、账号隔离和阅读进度并发更新。`tests/browser/history.spec.ts` 覆盖加载历史期间滚动、新消息到达以及图片延迟展开时的阅读位置。
